# แผน: ใบประเมินงานของพี่ช่าง (ระยะ 1 ของรอบ "อยากกลับมาเล่น")

เขียนเมื่อ 1 พ.ย. 2026 · **อนุมัติแล้ว 1 พ.ย. 2026** (ผู้ใช้: "อนุมัติ เริ่มระยะ 1")
รอบนี้มี 3 ระยะ: 1 ใบประเมินงาน (ข้อ 5) → 2 สมุดช่าง (ข้อ 4) → 3 ลูกค้าสุ่ม เลื่อนขั้นช่าง และแต่งร้าน (ข้อ 7)

## ปัญหาตอนนี้
หน้าสรุปเคสบอกแค่ว่า "เสียดาว: ลงมือพลาด 2 ครั้ง" เกมนับจำนวนครั้งที่พลาด แต่ไม่ได้จำว่าพลาดเรื่องอะไร
ผู้เรียนจึงไม่รู้ว่าต้องแก้ตรงไหน และไม่มีปุ่มให้ลองเคสเดิมอีกรอบ

## สิ่งที่ทำ
1. **จำเหตุผลที่พลาดทุกครั้ง:** session เก็บ `slips` (เหตุผลจากหน้าจอจำลอง เช่น ออกจาก BIOS ไม่บันทึก หรือลบพาร์ทิชันของ USB)
   - ดาวคิดเหมือนเดิมทุกอย่าง: ครั้งแรกไม่เสียดาว พลาดกี่ครั้งก็เสียแค่ 1 ดาว
2. **ใบประเมิน 3 เกณฑ์ (✓ / ✗) แทนรายการ "เสียดาว"**
   - **เดาสาเหตุ:** ถ้าผิด แสดงคำอธิบายของเคสนั้น
   - **ลงมือซ่อม:** แสดงทุกเรื่องที่พลาด พร้อม "จำไว้" ของแต่ละเรื่อง ถ้าพลาดครั้งเดียวได้ ✓ แต่บอกว่าครั้งแรกไม่เสียดาว
   - **อธิบายลูกค้า:** ถ้าผิด แสดงคำอธิบายของคำถามข้อแรกที่ตอบผิด
   - ข้อที่ ✗ มีป้าย "−1 ดาว"
   - **เหรียญเสริมแยกบรรทัด:** ไม่ใช้คำใบ้, ตารางข้อกำหนด, ถามเรื่องความเป็นส่วนตัว
   - บันทึกช่างยังอยู่เหมือนเดิม
3. **ปุ่ม "ลองอีกรอบให้ได้ 3 ดาว"** (แสดงเมื่อได้ไม่ถึง 3 ดาว)
   - ลูกค้าคนเดิมกลับมาพร้อมเครื่องที่สุ่มใหม่
   - ตอนรับเรื่อง พี่ช่างบอกว่ารอบนี้ควรเน้นเกณฑ์ไหน และก่อนเปิดเครื่องเตือน "จำไว้" ของเรื่องที่พลาดในรอบก่อน
   - เก็บดาวดีที่สุดเหมือนเดิม ครูยังเห็นดาวรอบแรกและดาวดีที่สุด
4. **ข้อความอยู่ใน `feedback.json`** ตรวจด้วย schema ร่างแรกเป็นของ Claude (`draft: true`) แล้วแทนด้วยข้อความจาก ChatGPT (prompt อยู่ใน docs/feedback-prompts.md)

## ผล (1 พ.ย. 2026)
- ทำครบทั้ง 4 ข้อ · ใส่ข้อความจาก ChatGPT แล้ว (ตัดคำว่า "จำไว้" ต้นประโยค tip ออก เพราะหน้าเกมใส่ "จำไว้:" ให้อยู่แล้ว)
- ใน {items} ส่วนลงมือซ่อมใช้ชื่อเกณฑ์ "ลงมือแก้ปัญหา" แทนชื่อเรื่องที่พลาด เพราะ "รอบนี้เน้น เครื่องกลับเข้า Windows ตัวเดิม" อ่านแปลก
- unit 271 · Playwright 444 · mutation 11/11 ถูกจับ · ภาพหน้าจอ 4 ขนาด

## ไม่เปลี่ยน
วิธีคิดดาว เหรียญ ความพอใจ ข้อมูลที่ส่งให้ครู หน้าจอจำลอง

## ตรวจ
- unit: session เก็บเหตุผลครบ, ใบประเมินตรงกับดาวทุกกรณี, schema ของ feedback.json ครอบคลุมเหตุผลทุกแบบ
- Playwright: ใบประเมินในเคส 1–5, ปุ่มลองอีกรอบ (พี่ช่างบอกเรื่องที่ต้องระวัง, ดาวดีที่สุดถูกเก็บ), ภาพหน้าจอ 4 ขนาด
- mutation และ `npm run check`
