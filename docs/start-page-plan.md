# หน้าเริ่มต้นก่อนเรียน + ชื่อเกมใหม่ WINSTALL (แผน · อนุมัติ 1 พ.ย. 2026)

## ทำไม

ตอนนี้ผู้เล่นใหม่เปิดเกมแล้วเจอฟอร์มกรอกชื่อบนหน้าร้านทันที ยังไม่รู้ว่าจะได้เรียนอะไร ต้องทำอะไรบ้าง ใช้เวลานานเท่าไร ตามหลักการออกแบบการสอน (ขั้น D ของ ADDIE, Gagné: เร้าความสนใจ → บอกวัตถุประสงค์) ควรมีหน้าแรกที่ทำสองอย่างนี้ก่อนเริ่ม

## ชื่อเกม (ผู้ใช้เลือก 1 พ.ย. 2026)

**WINSTALL** (Windows + Install + Win ที่แปลว่าชนะ) · ชื่อรอง: *ร้านซ่อมคอมพี่ช่าง · ภารกิจเด็กฝึกงาน ลง Windows 11*

เปลี่ยนทุกที่ให้ตรงกัน: `<title>` · ชื่อแอปตอนติดตั้ง (manifest) · หัวหน้าครู · คู่มือครู/คู่มือตั้งค่า · ข้อความในเกมที่เรียกชื่อเกม · ลิงก์เกมเดิมไม่เปลี่ยน · ชื่อ "ร้านของพี่ช่าง" ในเรื่องยังใช้ได้

## หน้าตา

**จังหวะ 1: จอบูต** จอดำแบบตอนเปิดเครื่อง ตัวอักษรพิกเซล "Press any key to start..." กะพริบ (ข้อความเดียวกับที่นักเรียนจะเจอจริงตอนบูต USB ในเคส) · แตะตรงไหนหรือกดปุ่มไหนก็ได้ → จังหวะ 2

**จังหวะ 2: หน้าเริ่มต้น** (แบนเนอร์เป็นฉากหลังด้านบน กล่องเดียว เลื่อนได้บนมือถือ)
1. **โลโก้ WINSTALL** ตัวอักษรในเกมเอง (ไม่ฝังในภาพ) + ชื่อรอง
2. **แบนเนอร์** (ChatGPT เจน → `npm run pixelize`): หน้าร้านพิกเซลอาร์ต เด็กฝึกงานถือแฟลชไดรฟ์ท่ามั่นใจ พี่ช่างยกนิ้วโป้ง คอมเปิดฝาบนโต๊ะ · ไม่มีตัวหนังสือในภาพ
3. **พี่ช่างทัก** ในกรอบคำพูด 1–2 ประโยค
4. **เรียนจบแล้วจะทำได้** วัตถุประสงค์ 4 ข้อ ภาษานักเรียน ข้อละ 1 บรรทัด
5. **สิ่งที่จะทำ** 7 ขั้น (ไอคอนเล็ก + ชื่อขั้น) และเวลาโดยประมาณ (คิดจากความยาวคลิปและเคสจริง) · "แบ่งเล่นหลายครั้งได้ เกมจำไว้ให้"
6. **ก่อนเริ่ม** ปุ่มเปิด/ปิดเสียง + "บทเรียนมีเสียงพากย์ ใส่หูฟังจะดีที่สุด"
7. **เปิดจากลิงก์ห้องเท่านั้น:** ป้าย "ห้อง ปวช.1/2 · ผลจะส่งให้ครูห้องนี้" (ชื่อห้องตามที่ครูพิมพ์ตอนสร้างลิงก์) + ปุ่ม **ไม่ใช่ห้องของฉัน** (เลิกส่งไปห้องนี้ บอกให้สแกน QR ของห้องตัวเอง)
8. ปุ่ม **เริ่มเลย** → ฟอร์มกรอกชื่อ (ฟอร์มเดิม) · ถ้า "ชั้น" ที่กรอกไม่ตรงกับห้องในลิงก์ → เตือนให้ตรวจอีกครั้ง (กรอกต่อได้)
9. **ส่วนท้าย:** รายวิชา 21910-2001 · ผู้จัดทำ · ลิงก์เล็ก "สำหรับครู" ไปหน้าครู

**ผู้เล่นที่กรอกชื่อแล้วไม่เห็นหน้านี้อีก** ไปที่เมนูเส้นทางตามเดิม · เมนูมีลิงก์เล็ก "เกี่ยวกับเกม" เปิดดูหน้านี้ซ้ำได้

## แอนิเมชัน (ผู้ใช้ขอเพิ่ม 1 พ.ย. 2026)

1. **จอบูต (2–3 วินาที):** ข้อความแบบ BIOS พิมพ์ทีละบรรทัด (`WINSTALL BIOS v1.0` · `Checking memory... OK` · `USB drive detected... OK` · `Press any key to start_`) บรรทัดสุดท้ายกะพริบรอ · แตะแล้วจอสว่างแบบจอ CRT เปิด
2. **โลโก้:** แถบ `Installing... 0% → 100%` เต็มแล้วโลโก้ WINSTALL เด้งขึ้น · ประกายวิบวับที่คำว่า WIN
3. **ฉาก:** แบนเนอร์ใหม่เป็นฉากหลัง · พี่ช่างใช้ชุดท่า `teach-*` ที่มีอยู่แล้ว (ยืน → ยกนิ้ว, กะพริบตา, ปากขยับตอนพูด) · เด็กฝึกงานท่าถือแฟลชไดรฟ์ 2 ภาพใหม่สลับกัน (ถือ ↔ ชูขึ้น) · ไฟป้าย/จอเรืองแสงทำด้วย CSS · กรอบคำพูดพิมพ์ทีละตัว
4. **รายการ:** วัตถุประสงค์และ 7 ขั้นเลื่อนเข้าทีละรายการ · ปุ่ม "เริ่มเลย" เต้นเบาๆ

หลัก: แตะเพื่อข้ามได้ทุกจังหวะ · รอดูรวมไม่เกิน 3–4 วินาที · จอบูตเห็นครั้งแรกครั้งเดียวต่อเครื่อง · `prefers-reduced-motion` แสดงหน้าเสร็จทันที · ใช้ CSS transform/opacity และสลับภาพ (ไม่โหลด Phaser ในหน้านี้)

## ปรับให้เหลือจอเดียว (1 พ.ย. 2026 ผู้ใช้: "หน้าเข้าเกมดูเยอะไป")

- เหลือ: โลโก้ · ชื่อรอง · พี่ช่างทัก + ตัวละคร · เวลา + ปุ่มเสียง · ปุ่มเริ่ม · "จบเกมนี้ เราจะทำได้ ▸" (พับไว้ กดเปิดดูวัตถุประสงค์ 4 ข้อ) · ลิงก์ "สำหรับครู" · ป้ายห้องย่อเป็นบรรทัดเดียว + ลิงก์ "ไม่ใช่ห้องของฉัน"
- ตัด: รายการ 7 ขั้น (เมนูแสดงอยู่แล้ว) · วิธีเล่น 3 ข้อ · ส่วนท้ายรายวิชา · ข้อความยังเก็บใน start.json
- มือถือแนวนอน: โลโก้และตัวละครซ้าย การ์ดขวา
- ตรวจแล้ว: เทสต์ 4 ขนาดจอว่าไม่มีอะไรให้เลื่อนและปุ่มเริ่มอยู่ในจอแรก · วัตถุประสงค์พับไว้แล้วเปิดได้ · ทำผิด 2 แบบ (เปิดวัตถุประสงค์ไว้ตั้งแต่แรก, ไม่มีเลย์เอาต์แนวนอน) เทสต์จับได้
