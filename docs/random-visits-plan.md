# แผน: ลูกค้ามาแบบสุ่ม ไม่ซ้ำกันสักรอบ (แบบเกม "1 in 8 Billion")

เขียนเมื่อ 25 ต.ค. 2026 · **อนุมัติแล้ว 25 ต.ค. 2026** (ข้อ 4):
1. ปิดงาน F ของเคส 2 ก่อน แล้วทำแผนนี้ ก่อนเคส 3
2. **เรื่องราวอยู่ในคลังกลาง** `stories.json` แต่ละเรื่องติดป้ายว่าเหมาะกับลูกค้าแบบไหนและปัญหาอะไร ตอนสุ่มดึงเฉพาะเรื่องที่เข้ากับปัญหาที่ได้ (ผู้ใช้เสนอ) · Claude ร่างเรื่องแรกๆ ผู้ใช้/ครูเพิ่มได้เองในไฟล์
3. **สุ่มตั้งแต่ลูกค้าคนแรก** (ไม่มีเคสเปิดตัวตายตัว) · ครั้งแรกๆ ได้ปัญหาเดียว · ตัวช่วยพี่ช่างขึ้นใน 2 ครั้งแรกที่เล่น · บทพูด คำถาม กับดักของเคส 1–2 ย้ายเข้าคลัง ไม่ทิ้ง
4. สมุดลูกค้าแบบง่ายในขั้นนี้

ข้อความด้านล่างเขียนก่อนตัดสินใจ: ที่บอกว่า "เคส 1–5 ยังอยู่เป็นเรื่องเปิดตัว" และ "เรื่องราวต่อคน" ให้ยึดข้อ 2–3 ข้างบนแทน
ที่มา: ผู้ใช้อยากให้ตัวละครหนึ่งตัวมีเคสได้หลายแบบไม่ซ้ำ แบบเกม "1 in 8 Billion" (เกิดใหม่แบบสุ่มทุกรอบ ชีวิตไม่ซ้ำกัน) · เลือก "สุ่มทุกครั้งที่มา"

## 1. ผู้เล่นจะเจออะไร

- **เคส 1–5 ที่เขียนไว้ยังอยู่** เป็นเรื่องเปิดตัวลูกค้าแต่ละคน (ครั้งแรกที่เจอ) และเป็นบทสอนทีละเรื่อง
- **หลังจากนั้นลูกค้าคนเดิมกลับมาอีกเรื่อยๆ แต่ทุกครั้งเกมสุ่มใหม่หมด:**
  - **ปัญหา** 1–2 อย่างจากคลัง (สุ่มแบบถ่วงน้ำหนัก: ปัญหาที่ร้านซ่อมเจอบ่อยออกบ่อยกว่า)
  - **เครื่อง** CPU · RAM · ดิสก์ สุ่มจากชุดสเปกที่สมจริง (ระบบนี้มีอยู่แล้ว)
  - **เรื่องราว** สุ่มจากชีวิตของลูกค้าคนนั้น เช่น ป้าสมศรี "หลานมาเล่นเกมแล้ว…" / "ซื้อเครื่องต่อจากลูกสาว…" · น้องบีม "ประกอบคอมใหม่เอง…" · ลุงชัย "ร้านมีเครื่องใหม่มาอีกเครื่อง…"
  - **บทพูด** ประกอบจากนิสัยของลูกค้า + อาการของปัญหาที่สุ่มได้ เช่น ป้าพูดสุภาพยาวๆ น้องบีมพูดเร็วมั่นใจ ลุงชัยเร่ง
  - **คำถามเดาสาเหตุ** และ **คำถามที่ลูกค้าถาม** สร้างจากปัญหาที่สุ่มได้ (ข้อถูก = สาเหตุจริง · ข้อหลอก = ความเข้าใจผิดที่พบบ่อยของปัญหานั้น)
- **"ไม่ซ้ำ" แบบสำรับไพ่:** เกมจำว่าผู้เล่นเจอปัญหาไหนไปแล้ว จะสุ่มปัญหาที่ยังไม่เคยเจอก่อน จนเจอครบทุกแบบแล้วค่อยวนใหม่ นักเรียนได้ฝึกครบทุกเรื่อง ไม่ใช่เจอเรื่องเดิมซ้ำเพราะดวง
- **ยากขึ้นตามที่เก่งขึ้น:** ครั้งแรกๆ ได้ปัญหาเดียว พอผ่านได้ 3 ดาวต่อเนื่อง เริ่มมี 2 ปัญหาซ้อนกันในเครื่องเดียว (ระบบตรวจว่าทุกชุดที่สุ่มแก้ได้จริงมีอยู่แล้วใน validator)
- **สมุดลูกค้า** (หน้าเล็กๆ): ดูว่าเคยซ่อมอะไรให้ใครไปแล้ว ปัญหาไหนยังไม่เคยเจอ (แสดงเป็น "???")

**เรื่องสถิติ (พูดตามจริง):** ไม่มีสถิติทางการว่าร้านซ่อมเจอปัญหาไหนบ่อยแค่ไหน น้ำหนักการสุ่มจึงเป็น**ค่าที่ครู/ผู้ทำเกมกำหนด** อยู่ในไฟล์เนื้อหา แก้ได้ ไม่อ้างว่าเป็นสถิติจริง ส่วนข้อกำหนดของ Windows 11 (RAM 4 GB, TPM 2.0, Secure Boot, UEFI) เป็นข้อมูลจริงจากไมโครซอฟต์

## 2. ปัญหาที่สุ่มได้ ขึ้นกับหน้าจอที่มี

| ปัญหา | ใช้ได้เมื่อ |
|---|---|
| USB ไม่ได้อยู่อันดับแรก · ตั้ง BIOS แล้วไม่บันทึก · USB ทำผิดแบบ (MBR) | **ตอนนี้** |
| Secure Boot ปิด · TPM ปิด | **เพิ่มได้ในขั้นนี้** (เมนูมีใน BIOS แล้ว เหลือให้หน้า "can't run Windows 11" บอกเหตุผลตามปัญหา) |
| ดิสก์ MBR บนเครื่อง UEFI · ไม่มี Product Key · Legacy+MBR | เมื่อทำหน้า Setup ทั้งเส้น + หน้าเลือกพาร์ทิชัน (เคส 3) |
| RAM/ดิสก์ไม่พอ (ต้องอัปเกรด) · RAID · ไดรเวอร์ | รอบหลัง |

ตอนนี้จึงมีปัญหา **5 แบบ** สุ่มได้ เป็นชุดปัญหาต่างกันราว 15 แบบ × เครื่องและเรื่องราวที่สุ่ม · เคส 3–4 เสร็จเมื่อไรจะเพิ่มเป็นราว 8–9 แบบเอง ไม่ต้องเขียนเคสใหม่

## 3. งานที่ต้องทำ

| # | งาน | ไฟล์ | ตรวจด้วย |
|---|---|---|---|
| R1 | **เนื้อหาต่อปัญหา**: สาเหตุ (ข้อถูก) + ความเข้าใจผิด (ข้อหลอก) สำหรับเดาสาเหตุ · คำถามลูกค้า + คำตอบ · น้ำหนักการสุ่ม | `problems.json`, `schema.ts` | validator |
| R2 | **เสียงของลูกค้า**: คำทักทาย คำปิด เรื่องราวชีวิต 4–6 เรื่องต่อคน บทพูดตอนพลาด/สำเร็จ/ลา (ย้ายจากเคสไปไว้ที่ตัวลูกค้า) | `customers.json` | validator |
| R3 | **ตัวสุ่มการมาร้าน**: เลือกปัญหาแบบสำรับไพ่ ถ่วงน้ำหนัก ยากขึ้นตามผลงาน · ประกอบบทพูด คำถาม · ผลเดิมทุกครั้งเมื่อใช้ seed เดิม | `src/core/visits.ts` (ใหม่) | unit test + mutation |
| R4 | **TPM / Secure Boot**: หน้า "can't run" บอกเหตุผลตามปัญหาจริง · ถ้ามี 2 ปัญหา ต้องแก้ครบถึงผ่าน | `pc.ts`, `screens.tsx` | unit test |
| R5 | **ต่อเข้าเกม**: หลังเคสเปิดตัวของแต่ละคน ลูกค้ามาแบบสุ่ม · จำสิ่งที่เคยเจอไว้ในเครื่อง · สมุดลูกค้า | `CaseFlow.tsx`, `progress.ts`, หน้าใหม่ | Playwright ทุกขนาดจอ |
| R6 | **ทดสอบ**: สุ่ม 1,000 ครั้ง ทุกครั้งต้องแก้ได้ ไม่มีบทพูดว่าง ไม่มีคำถามที่ข้อถูกซ้ำกับข้อหลอก · เล่นจริงหลายรอบ | tests | `npm run check` |

## 4. ต้องการให้ตัดสินใจ

| เรื่อง | ผมเสนอ | ทางเลือก |
|---|---|---|
| **ลำดับงาน** | ปิดงาน F ของเคส 2 ก่อน (ครึ่งวัน) แล้วทำแผนนี้ ก่อนเคส 3 | ทำแผนนี้ทันที งาน F ทำทีหลัง |
| **ใครเขียนเรื่องราวชีวิตลูกค้า** | ผมร่างให้คนละ 4–6 เรื่อง คุณตรวจ/แก้ได้ในไฟล์ | คุณเขียนเอง |
| **เมื่อไรเริ่มสุ่ม** | หลังเจอลูกค้าครบ 5 เคสเปิดตัว (ตอนนี้ที่มีแค่ 2 เคส: หลังเคส 2) | สุ่มตั้งแต่ลูกค้าคนแรก |
| **สมุดลูกค้า** | ทำแบบง่ายในขั้นนี้ | ทำทีหลัง |

## 5. ความเสี่ยง

- **ประโยคประกอบอาจฟังแข็ง** (ทักทาย + อาการ + ปิด) ถ้าอ่านแล้วไม่เป็นธรรมชาติ จะเขียนอาการแยกตามลูกค้าบางคนเพิ่ม
- **2 ปัญหาซ้อนกัน** อาจทำให้มือใหม่งง: ยากขึ้นเฉพาะหลังได้ 3 ดาวต่อเนื่อง และคำใบ้ชี้ทีละปัญหา
- คำถามที่สร้างอัตโนมัติต้องให้ครูตรวจ เพราะข้อหลอกที่ดีต้องมาจากความเข้าใจผิดจริงของนักเรียน
