# คู่มือครู การใช้เกมการศึกษา WINSTALL

**รายวิชา:** 21910-2001 ระบบปฏิบัติการเบื้องต้น  
**ระดับชั้น:** ประกาศนียบัตรวิชาชีพ (ปวช.)  
**เรื่อง:** การติดตั้งระบบปฏิบัติการ Windows 11  
**กลุ่มผู้ใช้:** ครูผู้สอนรายวิชาระบบปฏิบัติการเบื้องต้น

## เกี่ยวกับเกมการศึกษา

**WINSTALL** (ภารกิจเด็กฝึกงาน พิชิต Windows 11) เป็นเกมการศึกษาที่จำลองสถานการณ์ให้ผู้เรียนรับบทเป็นเด็กฝึกงานในร้านซ่อมคอมพิวเตอร์ ผู้เรียนจะได้ศึกษาขั้นตอนการติดตั้ง Windows 11 ฝึกเรียงลำดับการทำงาน และแก้ปัญหาจากสถานการณ์ลูกค้า

กิจกรรมการเรียนรู้มี 7 ขั้นตอน ตามลำดับดังนี้

1. **แบบทดสอบก่อนเรียน** — วัดความรู้พื้นฐานก่อนเริ่มเรียน
2. **บทเรียนวิดีโอ 2 คลิป** — ศึกษาเนื้อหาและตอบคำถามท้ายคลิปแต่ละคลิป
3. **เกมเรียงขั้นตอน** — ฝึกเรียงลำดับการติดตั้ง Windows 11
4. **เคสลูกค้า 5 เคส** — ฝึกนำความรู้ไปใช้แก้ปัญหาในสถานการณ์จำลอง
5. **แบบทดสอบหลังเรียน** — ประเมินความรู้หลังทำกิจกรรม
6. **สะท้อนผลและความพึงพอใจ** — ให้ผู้เรียนประเมินตนเอง แสดงความคิดเห็น และประเมินความพึงพอใจ
7. **สรุปผลการเรียน** — แสดงผลการเรียนรู้และสถานะการส่งผลให้ครู

ครูสามารถเก็บผลการเรียนรู้ผ่าน Google Sheet ของตนเอง และดูผลรวมของห้องเรียนผ่านหน้าครูของเกม

# ส่วนที่ 1 ตั้งค่าระบบครั้งแรก

การตั้งค่าทำเพียงครั้งแรก ใช้เวลาประมาณ 10 นาที โดยใช้บัญชี Google ของครูเอง

เมื่อตั้งค่าเสร็จ ผลของนักเรียนแต่ละห้องจะถูกบันทึกใน Google Sheet และครูสามารถดูผลสรุปผ่านหน้าครูของเกมได้

## 1.1 สิ่งที่ต้องเตรียม

1. บัญชี Google เช่น Gmail หรือบัญชี Google ของสถานศึกษา
2. คอมพิวเตอร์ที่เปิดเว็บไซต์ได้ (แนะนำให้ตั้งค่าบนคอมพิวเตอร์)
3. โค้ด Apps Script สำหรับรับผลนักเรียน
4. รหัสครูที่กำหนดเอง มีความยาวอย่างน้อย 8 ตัวอักษร และไม่ซ้ำกับรหัสผ่านอื่น

**ข้อควรทราบ:** รหัสครูใช้สำหรับดึงผลการเรียนรู้ นักเรียนไม่จำเป็นต้องทราบรหัสนี้

โค้ด Apps Script สามารถรับได้จาก [หน้าครูของเกม WINSTALL](https://nabaworn0.github.io/project-cai/?view=teacher) โดยใช้ปุ่ม

- **คัดลอกโค้ด Apps Script**
- **ดาวน์โหลดโค้ด (Code.gs)**

ทั้งสองวิธีใช้โค้ดเดียวกัน

## 1.2 ขั้นที่ 1 สร้าง Google Sheet

1. เปิดเว็บไซต์ https://sheets.new
2. ระบบจะสร้าง Google Sheet ใหม่
3. ตั้งชื่อไฟล์ที่มุมซ้ายบน เช่น `ผลเกมร้านซ่อมคอม 2569`
4. ไม่ต้องสร้างแท็บหรือหัวตารางเอง

เมื่อมีนักเรียนส่งผลครั้งแรก ระบบจะสร้างแท็บสำหรับห้องเรียนนั้นโดยอัตโนมัติ

## 1.3 ขั้นที่ 2 วางโค้ด Apps Script

1. ใน Google Sheet เลือกเมนู **ส่วนขยาย (Extensions) → Apps Script**
2. ระบบจะเปิดหน้า Apps Script ในแท็บใหม่
3. ตั้งชื่อโปรเจ็กต์ที่มุมซ้ายบน เช่น `รับผลเกมร้านซ่อมคอม`
4. เปิด [หน้าครูของเกม](https://nabaworn0.github.io/project-cai/?view=teacher) ในอีกแท็บหนึ่ง
5. กด **คัดลอกโค้ด Apps Script**
6. กลับไปที่ Apps Script แล้วเปิดไฟล์ `Code.gs`
7. ลบโค้ดเดิมทั้งหมด เช่น `function myFunction() {}`
8. วางโค้ดที่คัดลอกมา โดยกด `Ctrl+V`
9. กด **บันทึก** (รูปแผ่นดิสก์ หรือ `Ctrl+S`)

**หมายเหตุ:** หากคัดลอกโค้ดไม่ได้ ให้กด **ดาวน์โหลดโค้ด (Code.gs)** จากหน้าครู แล้วนำโค้ดในไฟล์มาวางแทน

## 1.4 ขั้นที่ 3 ตั้งรหัสครู

1. ใน Apps Script ไปที่แถบด้านซ้าย
2. กดรูปเฟือง **การตั้งค่าโปรเจ็กต์ (Project Settings)**
3. เลื่อนลงไปที่ **พร็อพเพอร์ตี้ของสคริปต์ (Script Properties)**
4. กด **เพิ่มพร็อพเพอร์ตี้ของสคริปต์ (Add script property)**
5. กรอกข้อมูลดังนี้

   - ช่อง **Property:** พิมพ์ `TEACHER_KEY` (ต้องเป็นตัวพิมพ์ใหญ่ทั้งหมด)
   - ช่อง **Value:** พิมพ์รหัสครูที่กำหนดไว้

6. กด **บันทึกพร็อพเพอร์ตี้ของสคริปต์ (Save script properties)**

**สำคัญ:** หากยังไม่ได้ตั้งรหัสครู นักเรียนจะส่งผลได้ตามปกติ แต่ครูจะยังดึงผลออกมาดูไม่ได้

## 1.5 ขั้นที่ 4 ทำให้ Apps Script เป็น Web app

Web app คือเว็บไซต์ขนาดเล็กที่ทำหน้าที่รับผลจากเกมและบันทึกลง Google Sheet

ดำเนินการดังนี้

1. ไปที่มุมขวาบนของ Apps Script
2. เลือก **การทำให้ใช้งานได้ (Deploy) → การทำให้ใช้งานได้รายการใหม่ (New deployment)**
3. กดรูปเฟืองข้าง **เลือกประเภท (Select type)**
4. เลือก **เว็บแอป (Web app)**
5. กำหนดค่าตามตาราง

| รายการ | ค่าที่ต้องตั้ง |
|---|---|
| คำอธิบาย | ตั้งได้ตามต้องการ เช่น `รุ่น 1` |
| ดำเนินการในฐานะ (Execute as) | **ฉัน (Me)** |
| ผู้ที่มีสิทธิ์เข้าถึง (Who has access) | **ทุกคน (Anyone)** |

**สำคัญ:** ต้องเลือก **ทุกคน (Anyone)** เพื่อให้นักเรียนส่งผลได้โดยไม่ต้องเข้าสู่ระบบ Google

6. กด **ทำให้ใช้งานได้ (Deploy)**

7. หาก Google ขออนุญาตเข้าถึงข้อมูลในครั้งแรก ให้ดำเนินการตามลำดับ

   - กด **ให้สิทธิ์เข้าถึง (Authorize access)**
   - เลือกบัญชี Google ของครู
   - หากมีข้อความ “Google ไม่ได้ยืนยันแอปนี้” ให้กด **ขั้นสูง (Advanced)**
   - กด **ไปที่ รับผลเกมร้านซ่อมคอม (ไม่ปลอดภัย)**
   - กด **อนุญาต (Allow)**

   ข้อความแจ้งเตือนนี้อาจเกิดขึ้นกับสคริปต์ที่ครูสร้างเอง โค้ดที่ให้มาตามคู่มือนี้ขอสิทธิ์แก้ไข Sheet ดังกล่าว และไม่ได้ส่งข้อมูลไปยังที่อื่น

8. คัดลอก **URL ของเว็บแอป (Web app URL)**

ลิงก์ที่ถูกต้องต้องลงท้ายด้วย `/exec`

เก็บลิงก์นี้ไว้สำหรับเชื่อมกับหน้าครูของเกม

## 1.6 ขั้นที่ 5 ตรวจสอบการตั้งค่า

1. เปิด URL ของเว็บแอปที่คัดลอกไว้ในเบราว์เซอร์
2. หากระบบทำงาน จะเห็นข้อความลักษณะนี้

   ```json
   {"ok":true,"app":"shop-sheet","note":"เว็บแอปรับผลของเกมร้านซ่อมคอมทำงานอยู่"}
   ```

3. เปิด [หน้าครูของเกม](https://nabaworn0.github.io/project-cai/?view=teacher)
4. ไปที่ส่วน **เชื่อมกับ Google Sheet ของครู**
5. วาง URL ของเว็บแอป
6. กรอกรหัสครูที่ตั้งไว้
7. กด **บันทึก**
8. ไปที่ส่วน **ลิงก์เกมสำหรับห้อง**
9. พิมพ์ชื่อห้อง เช่น `ปวช.1/2`
10. ตรวจสอบว่ามีลิงก์เกมและ QR ของห้อง
11. ไปที่ส่วน **ดึงผลของห้อง**
12. กด **ดูห้องใน Sheet**

หากยังไม่มีนักเรียนส่งผล ระบบจะแจ้งว่า **“ยังไม่มีผลส่งเข้ามาใน Sheet”** ซึ่งเป็นผลปกติ

## 1.7 การอัปเดตโค้ดภายหลัง

เมื่อมีโค้ดรุ่นใหม่ ให้ดำเนินการดังนี้

1. เปิด Apps Script ของ Google Sheet เดิม
2. วางโค้ดใหม่แทนโค้ดเดิม
3. กด **บันทึก**
4. เลือก **การทำให้ใช้งานได้ (Deploy) → จัดการการทำให้ใช้งานได้ (Manage deployments)**
5. กดรูปดินสอเพื่อแก้ไขการทำให้ใช้งานได้เดิม
6. ที่ **เวอร์ชัน (Version)** เลือก **เวอร์ชันใหม่ (New version)**
7. กด **ทำให้ใช้งานได้ (Deploy)**

**ข้อควรระวัง:** อย่าเลือก **การทำให้ใช้งานได้รายการใหม่ (New deployment)** ซ้ำ เพราะจะได้ URL ใหม่ ทำให้ลิงก์ห้องและ QR เดิมยังส่งผลไปยังระบบรุ่นเก่า

การใช้ **เวอร์ชันใหม่ (New version)** กับการทำให้ใช้งานได้เดิม จะช่วยให้ใช้ URL เดิมต่อได้

แหล่งอ้างอิงการตั้งค่า: เอกสารทางการของ Google เรื่อง [Properties Service](https://developers.google.com/apps-script/guides/properties) และ [Create and manage deployments](https://developers.google.com/apps-script/concepts/deployments)

# ส่วนที่ 2 การเก็บผลการเรียนรู้ในห้องเรียน

## 2.1 เชื่อมต่อ Google Sheet ของครู

1. เปิด [หน้าครูของเกม](https://nabaworn0.github.io/project-cai/?view=teacher)
2. ไปที่ส่วน **เชื่อมกับ Google Sheet ของครู**
3. วางลิงก์ Web app ที่ได้จากการตั้งค่าครั้งแรก
4. กรอกรหัสครู
5. กด **บันทึก**

ข้อมูลการเชื่อมต่อจะถูกเก็บไว้ในเครื่องที่ครูใช้งาน

## 2.2 สร้างลิงก์เกมสำหรับห้องเรียน

1. ไปที่ส่วน **ลิงก์เกมสำหรับห้อง**
2. พิมพ์ชื่อห้อง เช่น `ปวช.1/2`
3. ระบบจะแสดงลิงก์เกมและ QR สำหรับห้องนั้น
4. กด **คัดลอกลิงก์** หากต้องการส่งลิงก์ให้นักเรียน
5. ให้นักเรียนสแกน QR หรือเปิดลิงก์ห้องเรียน

ชื่อห้องใช้ได้เฉพาะตัวอักษร ตัวเลข และเครื่องหมาย `. / _ -` โดยมีความยาวไม่เกิน 30 ตัวอักษร

## 2.3 การเข้าเรียนของนักเรียน

เมื่อนักเรียนเปิดเกมผ่านลิงก์หรือ QR ของห้องเรียน ให้ดำเนินการดังนี้

1. กรอกชื่อ
2. กรอกชั้นเรียน
3. กรอกเลขที่
4. ทำกิจกรรมในเกมตามลำดับที่กำหนด

เมื่อนักเรียนทำแต่ละขั้นตอนเสร็จ เกมจะส่งผลไปยัง Google Sheet ของครูโดยอัตโนมัติ

**นักเรียนไม่ต้องกดส่งผลด้วยตนเอง**

เมื่อนักเรียนเปิดลิงก์ห้องเรียนแล้ว การเปิดเกมผ่านลิงก์ปกติครั้งต่อไปบนเครื่องเดิมจะยังส่งผลเข้าห้องเดิม

## 2.4 กรณีอินเทอร์เน็ตขัดข้อง

หากอินเทอร์เน็ตหลุดระหว่างเรียน เกมจะเก็บผลไว้และพยายามส่งใหม่โดยอัตโนมัติเมื่อกลับมาเชื่อมต่ออินเทอร์เน็ต

นักเรียนตรวจสอบสถานะการส่งได้ที่หน้า **สรุปผลการเรียน**

หากยังส่งผลไม่ได้ ให้ใช้วิธีสำรองดังนี้

1. ให้นักเรียนเปิดหน้า **สรุปผลการเรียน**
2. กด **ดาวน์โหลดไฟล์ผล**
3. ส่งไฟล์ผลที่ดาวน์โหลดให้ครู
4. ครูนำไฟล์ไปเปิดรวมผลในหน้าครู

## 2.5 คำแนะนำการใช้ในคาบเรียน

ก่อนเริ่มเรียน ครูควรตรวจสอบการเชื่อมต่อ Google Sheet และเตรียมลิงก์หรือ QR ของห้องเรียน เมื่อเริ่มคาบ ให้นักเรียนกรอกชื่อ ชั้น และเลขที่ให้ถูกต้อง แล้วทำกิจกรรมตามลำดับ ตั้งแต่แบบทดสอบก่อนเรียนจนถึงหน้าสรุปผล ครูควรดูแลการทำกิจกรรมและช่วยเหลือนักเรียนที่พบปัญหา เมื่อจบคาบ ให้ตรวจสอบจำนวนผู้เรียนที่ส่งผลและใช้ผลการเรียนรู้วางแผนสอนซ่อมเสริม

# ส่วนที่ 3 การรวมผลการเรียนรู้

ครูสามารถรวมผลได้ 2 วิธี ได้แก่ ดึงผลจาก Google Sheet หรือใช้ไฟล์ผลที่นักเรียนดาวน์โหลด

## 3.1 วิธีที่ 1 ดึงผลจาก Google Sheet

1. เปิดหน้าครูของเกม
2. ไปที่ส่วน **ดึงผลของห้อง**
3. กด **ดูห้องใน Sheet**
4. เลือกห้องเรียนที่ต้องการ
5. กด **ดึงผล**
6. ตรวจสอบผลการเรียนรู้ที่แสดงในหน้าครู

เหมาะสำหรับห้องเรียนที่นักเรียนส่งผลผ่านอินเทอร์เน็ตตามปกติ

## 3.2 วิธีที่ 2 รวมผลจากไฟล์นักเรียน

ใช้เมื่อครูได้รับไฟล์ผลจากนักเรียน เช่น กรณีอินเทอร์เน็ตขัดข้อง

1. ให้นักเรียนส่งไฟล์ผลนามสกุล `.json`
2. เปิดหน้าครูของเกม
3. ลากไฟล์ผลของนักเรียนหลายไฟล์มาวางในบริเวณรับไฟล์ หรือกดเลือกหลายไฟล์
4. ตรวจสอบผลการเรียนรู้ที่ระบบนำมารวม

ไฟล์ `.json` คือไฟล์ที่เก็บข้อมูลผลการเรียนของนักเรียนในรูปแบบที่เกมสามารถอ่านได้

### กรณีนักเรียนส่งผลหลายครั้ง

หากนักเรียนคนเดิมส่งผลหลายครั้ง ระบบจะใช้ **ผลที่ส่งล่าสุด** ในการรวมผล

### กรณีไฟล์ผลถูกแก้ไข

หากมีการแก้ไขไฟล์ผลหลังจากดาวน์โหลด ระบบจะแสดงคำเตือนพร้อมเลขที่นักเรียน

ครูควรตรวจสอบไฟล์ดังกล่าวกับนักเรียนก่อนนำผลไปใช้

### กรณีข้อมูลบางแถวอ่านไม่ได้

หากข้อมูลจาก Google Sheet บางแถวอ่านไม่ได้ ระบบจะแจ้งเลขแถวที่มีปัญหา

ครูสามารถตรวจสอบแถวดังกล่าวได้โดยตรงใน Google Sheet

## 3.3 ข้อมูลที่จัดเก็บใน Google Sheet

ระบบจัดเก็บข้อมูลแยกตามห้องเรียน โดยมีรายละเอียดดังนี้

- **หนึ่งแท็บต่อหนึ่งห้องเรียน** ชื่อแท็บตรงกับชื่อห้องที่กำหนด
- **หนึ่งแถวต่อนักเรียนหนึ่งคน** โดยใช้ชั้นเรียนและเลขที่ในการระบุผู้เรียน
- เมื่อนักเรียนส่งผลซ้ำ ระบบจะปรับปรุงแถวเดิม ไม่สร้างแถวใหม่

หากมีแท็บที่ครูสร้างเองและใช้ชื่อเดียวกับห้องเรียนอยู่ก่อน ระบบจะไม่แก้ไขแท็บนั้น แต่จะสร้างแท็บใหม่ชื่อ `ชื่อห้อง (เกม)` แทน

ข้อมูลใน Sheet ประกอบด้วยคอลัมน์ต่อไปนี้

| คอลัมน์ | ข้อมูลที่แสดง |
|---|---|
| ห้อง | ชื่อห้องเรียน |
| เลขที่ | เลขที่นักเรียน |
| ชื่อ-สกุล | ชื่อนักเรียน |
| ก่อนเรียน | คะแนนแบบทดสอบก่อนเรียน |
| หลังเรียน | คะแนนแบบทดสอบหลังเรียน |
| เคสที่เล่น | จำนวนเคสลูกค้าที่ทำ |
| ดาวเคสรวม | จำนวนดาวรวมจากเคสลูกค้า |
| ส่งล่าสุด | เวลาที่ส่งผลล่าสุด |
| ข้อมูลเต็ม | ข้อมูลผลการเรียนรู้ที่ใช้คำนวณในหน้าครู |

**ข้อควรระวัง**

- ห้ามแก้ไขคอลัมน์ **ข้อมูลเต็ม** เพราะหน้าครูใช้ข้อมูลนี้คำนวณผลการเรียนรู้
- หากเผลอแก้ไข ระบบจะแจ้งแถวที่อ่านไม่ได้ เมื่อนักเรียนส่งผลใหม่ ข้อมูลแถวดังกล่าวจะกลับมาถูกต้อง
- ครูสามารถลบแถวของนักเรียนที่ส่งผลผิดห้องได้
- ห้ามแก้ไขหัวตารางแถวที่ 1 เพราะระบบใช้ระบุแท็บห้องเรียน

## 3.4 การนำผลไปใช้งานต่อ

เมื่อรวมผลเรียบร้อยแล้ว ครูสามารถใช้ปุ่มต่อไปนี้

### ดาวน์โหลด CSV (Excel)

กด **ดาวน์โหลด CSV (Excel)**

ระบบจะดาวน์โหลดข้อมูลในรูปแบบ CSV (ไฟล์ตารางข้อมูลที่เปิดด้วย Microsoft Excel ได้)

เหมาะสำหรับ

- จัดเก็บผลการเรียนรู้
- นำข้อมูลไปประกอบรายงานการจัดการเรียนรู้
- วิเคราะห์ผลเพิ่มเติมด้วย Excel

### พิมพ์หน้านี้

กด **พิมพ์หน้านี้**

เหมาะสำหรับ

- พิมพ์ผลสรุปไว้เป็นหลักฐาน
- ใช้ประกอบรายงานผลการจัดการเรียนรู้
- นำเสนอผลการเรียนรู้ต่อผู้เกี่ยวข้อง

# ส่วนที่ 4 การอ่านและใช้ผลการเรียนรู้

หน้าครูแสดงผลการเรียนรู้ทั้งระดับห้องเรียน ระดับรายบุคคล และระดับข้อสอบ เพื่อช่วยครูประเมินผลและปรับปรุงการสอน

## 4.1 คะแนนก่อนเรียนและหลังเรียน

ระบบแสดงข้อมูลดังนี้

- ค่าเฉลี่ยคะแนนก่อนเรียน
- ค่าเฉลี่ยคะแนนหลังเรียน
- ส่วนเบี่ยงเบนมาตรฐาน (S.D.)
- ค่าเฉลี่ยคะแนนที่เพิ่มขึ้นหลังเรียน

สัญลักษณ์ที่ใช้

- **x̄** หมายถึง คะแนนเฉลี่ยของผู้เรียน
- **S.D.** หมายถึง ส่วนเบี่ยงเบนมาตรฐาน ใช้บอกว่าคะแนนของผู้เรียนแตกต่างหรือกระจายจากค่าเฉลี่ยมากน้อยเพียงใด

**การนำไปใช้:** ครูเปรียบเทียบคะแนนก่อนและหลังเรียน เพื่อพิจารณาว่าผู้เรียนมีความรู้เพิ่มขึ้นเพียงใด และนำไปเขียนรายงานผลการจัดการเรียนรู้

## 4.2 ประสิทธิภาพของเกม E1/E2

ใช้เกณฑ์ **80/80** ในการพิจารณาประสิทธิภาพของเกมการศึกษา

| ตัวชี้วัด | ความหมาย |
|---|---|
| **E1** | ร้อยละเฉลี่ยของผลการเรียนรู้ระหว่างเรียน |
| **E2** | ร้อยละเฉลี่ยของคะแนนแบบทดสอบหลังเรียน |

### การคำนวณ E1

พิจารณาจากผลระหว่างเรียน ได้แก่

1. คำถามท้ายคลิปวิดีโอที่ตอบถูกในการตอบครั้งแรก
2. ดาวที่ได้รับจากการเล่นเกมเรียงขั้นตอนในรอบแรก
3. ดาวที่ได้รับจากการทำเคสลูกค้าในรอบแรก

### การคำนวณ E2

คำนวณจากร้อยละเฉลี่ยของคะแนนแบบทดสอบหลังเรียน

**ข้อควรทราบ:** การคำนวณ E1/E2 ใช้ข้อมูลเฉพาะผู้เรียนที่ทำแบบทดสอบหลังเรียนแล้ว

### การแปลผล

- E1 ตั้งแต่ 80 และ E2 ตั้งแต่ 80 หมายถึง ผ่านเกณฑ์ประสิทธิภาพ 80/80
- หากค่าใดต่ำกว่า 80 หมายถึง ยังไม่ผ่านเกณฑ์ที่กำหนด

**การนำไปใช้:** ครูใช้ประเมินประสิทธิภาพของเกม และระบุส่วนที่ควรปรับปรุง เช่น บทเรียนวิดีโอ เกมเรียงขั้นตอน หรือเคสลูกค้า

## 4.3 การเปรียบเทียบคะแนนด้วย t-test

ระบบใช้ **t-test แบบไม่อิสระ (dependent t-test)** ซึ่งเป็นการทดสอบความแตกต่างของคะแนนก่อนและหลังเรียนจากผู้เรียนคนเดียวกัน

เป็นการทดสอบทางเดียว โดยพิจารณาว่าคะแนนหลังเรียนสูงกว่าก่อนเรียนหรือไม่ ที่ระดับนัยสำคัญทางสถิติ `.05`

ระบบจะแสดงผลเมื่อมีผู้เรียนที่ทำแบบทดสอบทั้งก่อนและหลังเรียน **อย่างน้อย 5 คน**

ค่าที่แสดงประกอบด้วย

| ค่า | ความหมาย |
|---|---|
| t | ค่าสถิติที่ใช้ทดสอบความแตกต่างของคะแนน |
| df | องศาอิสระ (ค่าที่เกี่ยวข้องกับจำนวนข้อมูลในการทดสอบ) |
| p | ค่าที่ใช้พิจารณานัยสำคัญทางสถิติ |

### การอ่านผล

- **p < .05** หมายถึง คะแนนหลังเรียนสูงกว่าก่อนเรียนอย่างมีนัยสำคัญทางสถิติที่ระดับ .05
- **p ≥ .05** หมายถึง ยังไม่พบว่าคะแนนหลังเรียนสูงกว่าก่อนเรียนอย่างมีนัยสำคัญทางสถิติที่ระดับ .05

ระบบจะแสดงประโยคสรุปว่าผลแตกต่างอย่างมีนัยสำคัญหรือไม่

**การนำไปใช้:** ครูใช้ผลการทดสอบประกอบการเขียนรายงานผลการจัดการเรียนรู้ โดยพิจารณาร่วมกับคะแนนเฉลี่ยและจำนวนผู้เรียน

## 4.4 ผลการเรียนรู้ตามวัตถุประสงค์

ระบบแสดงร้อยละที่ตอบถูกของทั้งห้อง ก่อนเรียนและหลังเรียน แยกตามวัตถุประสงค์การเรียนรู้ทั้ง 4 ข้อ

**การอ่านผล:** วัตถุประสงค์ที่มีร้อยละการตอบถูกต่ำ แสดงว่าผู้เรียนยังมีความเข้าใจเนื้อหาส่วนนั้นไม่เพียงพอ

**การนำไปใช้:** ครูใช้เลือกเนื้อหาที่ควรอธิบายเพิ่มเติม จัดกิจกรรมฝึกซ้ำ หรือปรับปรุงการสอนให้ตรงกับวัตถุประสงค์ที่ผู้เรียนยังทำได้ไม่ดี

## 4.5 ตารางผลการเรียนรู้รายบุคคล

ระบบแสดงข้อมูลผู้เรียนแต่ละคน เช่น

| ข้อมูล | ใช้พิจารณา |
|---|---|
| คะแนนก่อนเรียน | ความรู้พื้นฐานของผู้เรียน |
| คะแนนหลังเรียน | ความรู้หลังทำกิจกรรม |
| ผลระหว่างเรียน | ผลการทำกิจกรรมในเกม |
| จำนวนขั้นตอนที่ทำครบ | ความก้าวหน้าในการเรียน |
| ส่งล่าสุด | เวลาที่ระบบได้รับผลล่าสุด |

**การนำไปใช้:** ครูติดตามผู้เรียนที่ทำกิจกรรมไม่ครบ หรือมีคะแนนหลังเรียนต่ำ เพื่อให้คำแนะนำและสอนเสริมรายบุคคล

## 4.6 การวิเคราะห์ข้อสอบรายข้อ

ระบบแสดงร้อยละของผู้เรียนที่ตอบถูกในแต่ละข้อ

**ข้อสอบที่มีผู้เรียนตอบถูกหลังเรียนไม่ถึง 50% จะแสดงเป็นสีแดง**

ระบบยังแสดงตัวเลือกผิดที่ผู้เรียนเลือกบ่อย เพื่อช่วยระบุความเข้าใจที่คลาดเคลื่อน

**การนำไปใช้**

- สอนซ้ำในหัวข้อที่ผู้เรียนตอบผิดจำนวนมาก
- อธิบายเหตุผลว่าทำไมตัวเลือกที่นักเรียนเลือกบ่อยจึงไม่ถูกต้อง
- ตรวจสอบความชัดเจนของคำถามและตัวเลือก
- ใช้ผลประกอบการปรับปรุงบทเรียนและข้อสอบ

## 4.7 ผลการประเมินความพึงพอใจ

ระบบแสดงผลความพึงพอใจ 3 ระดับ ได้แก่

1. รายข้อ
2. รายด้าน
3. ภาพรวมทั้งหมด

แต่ละระดับแสดงค่าเฉลี่ย (x̄) และส่วนเบี่ยงเบนมาตรฐาน (S.D.)

### เกณฑ์แปลผลความพึงพอใจ

| ค่าเฉลี่ย | ระดับความพึงพอใจ |
|---|---|
| 4.51–5.00 | มากที่สุด |
| 3.51–4.50 | มาก |
| 2.51–3.50 | ปานกลาง |
| 1.51–2.50 | น้อย |
| 1.00–1.50 | น้อยที่สุด |

**การนำไปใช้:** ครูใช้ประเมินความคิดเห็นของผู้เรียนต่อเกมการศึกษา และใช้ประกอบการปรับปรุงสื่อการสอน รวมถึงการเขียนรายงานผลความพึงพอใจ

## 4.8 ผลการสะท้อนการเรียนรู้ของผู้เรียน

ระบบแสดงข้อมูล 2 ส่วน

1. **การประเมินตนเอง** — ผู้เรียนให้คะแนนตนเองตั้งแต่ 1–5 ดาว
2. **คำตอบที่ผู้เรียนเขียน** — ความคิดเห็นหรือข้อสะท้อนจากประสบการณ์การเรียนรู้

**การนำไปใช้:** ครูอ่านความคิดเห็นเพื่อทำความเข้าใจปัญหา ความต้องการ และประสบการณ์ของผู้เรียน แล้วนำข้อมูลไปปรับปรุงกิจกรรมหรือให้คำแนะนำรายบุคคล

## 4.9 ข้อจำกัดที่ควรรู้

1. **ต้องมีอินเทอร์เน็ตในการส่งผล**  
   หากไม่มีอินเทอร์เน็ต เกมจะพยายามส่งผลใหม่เมื่อกลับมาออนไลน์

2. **ลิงก์ห้องเรียนไม่ได้ป้องกันการส่งข้อมูลจากบุคคลอื่น**  
   ผู้ที่ทราบลิงก์ห้องสามารถส่งผลเข้ามาได้ ระบบนี้ไม่ได้ป้องกันการทุจริตเหมือนระบบสอบ ครูจึงควรตรวจสอบชื่อและเลขที่นักเรียน

3. **ข้อมูลนักเรียนต้องเก็บเป็นความลับ**  
   Google Sheet มีข้อมูลชื่อของนักเรียน ครูไม่ควรแชร์ Sheet หรือรหัสครูให้บุคคลอื่น

4. **สามารถเปลี่ยนรหัสครูได้**  
   หากลืมรหัส ให้กลับไปที่การตั้งค่า `TEACHER_KEY` ตามส่วนที่ 1 ขั้นที่ 3 แล้วดูหรือกำหนดรหัสใหม่ การเปลี่ยนรหัสไม่จำเป็นต้อง Deploy ใหม่

## 4.10 ปัญหาที่พบบ่อย

### คำถามที่ 1: ระบบแจ้งว่า “รหัสครูไม่ถูกต้อง” ต้องทำอย่างไร?

**คำตอบ:** ตรวจสอบรหัสครูที่กรอกในหน้าครูให้ตรงกับค่า `TEACHER_KEY` ใน Apps Script

หากลืมรหัส ให้เปิด **การตั้งค่าโปรเจ็กต์ (Project Settings)** และตรวจสอบค่าที่ **พร็อพเพอร์ตี้ของสคริปต์ (Script Properties)**

### คำถามที่ 2: ระบบแจ้งว่า “ติดต่อ Sheet ไม่ได้” ต้องทำอย่างไร?

**คำตอบ:**

1. ตรวจสอบการเชื่อมต่ออินเทอร์เน็ต
2. ตรวจสอบลิงก์ Web app ว่าลงท้ายด้วย `/exec`
3. ลองเปิดลิงก์ Web app ในเบราว์เซอร์ เพื่อดูว่าระบบรับผลทำงานอยู่หรือไม่
4. ตรวจสอบว่าได้ตั้งค่าการใช้งานเป็น **ทุกคน (Anyone)** แล้ว

### คำถามที่ 3: กด “ดูห้องใน Sheet” แล้วไม่มีห้องเรียน ต้องทำอย่างไร?

**คำตอบ:** หากยังไม่มีนักเรียนส่งผลเข้ามา จะยังไม่มีแท็บห้องเรียนใน Sheet

ให้นักเรียนเปิดลิงก์หรือ QR ของห้อง แล้วกรอกชื่อ ชั้น และเลขที่ให้เรียบร้อย (เกมส่งผลครั้งแรกทันทีหลังกรอกชื่อ) จากนั้นครูกด **ดูห้องใน Sheet** อีกครั้ง

### คำถามที่ 4: นักเรียนแจ้งว่ายังส่งผลไม่ได้ ต้องทำอย่างไร?

**คำตอบ:**

1. ตรวจสอบอินเทอร์เน็ตของนักเรียน
2. ให้นักเรียนดูสถานะการส่งในหน้า **สรุปผลการเรียน**
3. หากอินเทอร์เน็ตขัดข้อง ให้เชื่อมต่อใหม่และรอเกมส่งผลอัตโนมัติ
4. หากยังส่งไม่ได้ ให้นักเรียนกด **ดาวน์โหลดไฟล์ผล** แล้วส่งไฟล์ให้ครู

### คำถามที่ 5: แก้ไขโค้ดแล้วลิงก์เดิมใช้ไม่ได้ ต้องทำอย่างไร?

**คำตอบ:** ตรวจสอบว่าได้อัปเดตการทำให้ใช้งานได้เดิมหรือไม่

วิธีที่ถูกต้องคือ

**การทำให้ใช้งานได้ (Deploy) → จัดการการทำให้ใช้งานได้ (Manage deployments) → รูปดินสอ → เวอร์ชันใหม่ (New version) → ทำให้ใช้งานได้ (Deploy)**

ไม่ควรสร้าง **การทำให้ใช้งานได้รายการใหม่ (New deployment)** เพราะจะได้รับ URL ใหม่

### คำถามที่ 6: ระบบแจ้งว่าข้อมูลบางแถวอ่านไม่ได้ ต้องทำอย่างไร?

**คำตอบ:** ตรวจสอบเลขแถวที่ระบบแจ้งใน Google Sheet โดยเฉพาะคอลัมน์ **ข้อมูลเต็ม**

หากข้อมูลถูกแก้ไขโดยไม่ตั้งใจ ให้นักเรียนเจ้าของข้อมูลทำกิจกรรมในเกมอีกครั้งเพื่อส่งผลใหม่ ระบบจะปรับปรุงข้อมูลในแถวเดิมให้ถูกต้อง
